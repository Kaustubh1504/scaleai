# prob-010 rubric — Document Triage with Confidence Routing

Score each category 1–4. **4** = strong hire signal, **3** = hire, **2** = lean no, **1** = no.
Descriptions of 3 and 1 interpolate between the two given. Write down evidence, not impressions.

| Category | 4 looks like (this problem) | 2 looks like (this problem) |
|---|---|---|
| **Correct execution** | Parts 1 and 2 pass the hidden tests including the reason change; Part 3 passes or nearly does. `>=` at the threshold, failed classifications routed with `classification_failed`, queue ordered by time-entered then upload order, 422 → 404 → 409 → reason order right, every transition has exactly one event, `seq` survives a restart. | Routing works for the happy path but failed classifications crash or get auto-accepted; review returns 200 for `auto_accepted` documents or accepts `"Contract"`; events are missing for failures or appended for rejected requests; `seq` restarts at 1 after a restart. |
| **Debugging & unblocking** | When a test fails, reads the traceback and the actual JSON, prints the document's `classification` and the trail, and finds the cause quickly (stale `storage/intake.db` after a schema change, a missing `version` bump, a second transaction). Reproduces a failure on purpose with `prompt_faults` or a `FunctionResponder`. Writes the 8-thread test, sees two 200s, and can explain the interleaving before fixing it. | Changes code until tests pass without a hypothesis; needs hint 2+ to see that `CREATE TABLE IF NOT EXISTS` kept the old schema; cannot get a threaded test to show the race, or concludes "it works on my machine" from a single-threaded run. |
| **Systematic thinking** | Reads the repo first and names the seams: store methods are transactions, the model is called outside them, `save_classification` overwrites, classify re-runs everything. Puts routing in a pure function, each transition in one store method that checks + updates + appends, and the reason rule becomes one more precondition there. Part 3's re-run rule is a `WHERE status = 'ingested'` plus a re-check at write time. | Starts typing in `main.py` before reading `db.py`; status logic spread across route handlers; events appended from the handler after the store call; the reason rule duplicated; Part 3 bolts on a global `threading.Lock` around every route without explaining what it protects. |
| **Production quality** | One transaction per transition; no in-memory state that matters; injected clock everywhere; parameterized SQL (even for the dynamic filter); clear 409 messages naming the current status; validation in the request model; append-only audit enforced or at least never exposed for update; does not hold the DB lock during model calls; validates `auto_accept_threshold` / `consistency_samples`. | `time.time()` for `ts`; f-string SQL with request values; a status change and its event in separate transactions; bare `except` turning sqlite errors into 409s; counters or the queue kept in a dict; LLM called inside a write transaction, serializing the whole service. |
| **Testing** | Tests written alongside code with `FakeClock` and pinned confidences (`FunctionResponder` or known keyword texts): the threshold boundary, each 409/422 case, queue ordering across two batches, the exact event sequence for auto / review / failed, filters, a restart test over the same `tmp_path`, a `threading.Barrier` review race that fails on a racy version, a re-run that asserts zero model calls and an unchanged trail. Reruns the 9 existing tests. | Only happy-path tests; relies on whatever confidences the sample data happens to produce; no restart or concurrency test; does not rerun the existing tests after changing the schema. |
| **End-to-end ownership** | Runs the server (`--factory`), uploads `data/documents.jsonl`, classifies, works the queue with curl as two reviewers, and reads the audit trail; reads the sample data's bad rows; ends with a summary of what is done, what is not, and known limits (SQLite single writer, no claim/lease on queue items, LLM self-confidence is uncalibrated). | Stops when unit tests pass without exercising the API; leaves `GET /batches` showing the old document shape; TODOs left unexplained. |
| **Communication** | States the decisions the spec leaves open (where `routed_at` lives, SQLite table vs JSONL for the trail, CAS vs lock) and why; flags trade-offs ("a re-run never retries failed documents, so a provider outage fills the queue: we may want an explicit retry endpoint"); explains the review race as a concrete interleaving; asks sharp questions (should a failed classification require a reason?) and finds the answer in the spec or the change wording. | Silent for long stretches; asks questions the PART files answer (e.g. the queue order); cannot explain why their review is or is not atomic. |

## Hidden-test mapping

| Test file | Covers |
|---|---|
| `test_part1.py` | `ingested` start state, routing by confidence (default, 0, 0.5, 0.96, 1), `>=` at 0.80, failed and non-retryable classifications → `classification_failed`, document shape in `GET /documents`, batch view and classify response, queue contents and order across two batches, review success / override / failed-classification, reviewer stripped, 409 (ingested, auto_accepted, already reviewed), 422 body cases leave the document unchanged, 404s, persistence across a restart |
| `test_part2.py` | event shape, `ingested` events (and none for rejected rows), exact trails for auto / review / failed, `reviewed` event actor + ts + details, 4xx appends nothing, global order and count, per-document trail equals the filtered global trail, immutability, `actor` / `action` / `since` filters alone and combined, 422 filters, 404, restart keeps events and `seq` grows; reason required for overrides, trimmed, optional when agreeing or without a model label, after the 409 check (`change`) |
| `test_part3.py` | `version` 1 → 2 → 3 (also in the queue), stale `expected_version` 409 with no event, 8-thread review race (exactly one 200 and one `reviewed` event, with and without `expected_version`), re-run makes zero model calls and changes nothing (also after a restart, also for failed documents), new batch classified normally, concurrent classify runs record each document once, two samples per document, disagreement → `disagreement`, minimum confidence, attempts summed, failed first / second sample, `ValueError` for 0 or 3 samples |

Use hidden-test results as evidence for **Correct execution** only; the other
categories come from watching the candidate work.
