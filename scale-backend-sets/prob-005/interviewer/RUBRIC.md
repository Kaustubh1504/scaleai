# prob-005 rubric — Webhook Delivery Dispatcher

Score each category 1–4. **4** = strong hire signal, **3** = hire, **2** = lean no, **1** = no.
Descriptions of 3 and 1 interpolate between the two given. Write down evidence, not impressions.

| Category | 4 looks like (this problem) | 2 looks like (this problem) |
|---|---|---|
| **Correct execution** | Parts 1 and 2 pass the hidden tests, including the timeout change. Part 3 passes, or misses at most one crash test. Signatures verify first time because they sign the bytes they send. Line numbers, duplicate ids, Retry-After exactness and "dead on the final attempt" are right without prompting. | Deliveries go out but signatures fail, or delivered events are re-sent; retries happen inline or on every call regardless of schedule; dead-lettering is missing or off by one; state is in memory only. |
| **Debugging & unblocking** | When the receiver reports `signature_valid=False`, compares the signed bytes with `request.content` and finds the `json=` re-serialization (or the `time.time()` clock) in minutes. Uses `receiver.deliveries`, `attempts_for()` and `clock.set()` to reproduce a schedule bug on purpose. | Changes the signing code at random; needs hint 2 to discover the body mismatch; stuck >5 min because a test advanced the real clock instead of the FakeClock. |
| **Systematic thinking** | Reads the repo first and names what exists (`wants`, `sign`, the swallowed bad lines, unused `max_attempts`/`timeout_s`). Models the (event, subscription) delivery as the unit of state. Separates send → classify → record. The timeout change is a one-line edit to a classification table. | Starts coding before reading; state keyed by event id only; classification is nested if/else inside the loop with duplicated audit-writing code in each branch; the change needs edits in several places. |
| **Production quality** | Atomic state writes (temp + fsync + `os.replace`) or sqlite, done after every attempt. Non-httpx exceptions propagate; httpx errors never escape. A corrupt state file is refused, not silently reset. Audit is append-only. Injected clock and client everywhere. Clear `last_error` strings; logging of failures. | Writes `state.json` in place; saves once at the end of the run; bare `except Exception` that records crashes as failures; `time.sleep` for backoff; audit opened with `"w"`; reads `time.time()`. |
| **Testing** | Tests alongside each part: routing/signature test with the mock receiver, scripted 5xx/429/4xx sequences asserting `next_attempt_at` bounds with `clock.set`, a max-attempts test, and a restart test that builds a second `Dispatcher` over the same `state_dir`. Bonus: a crash test (client raising mid-run). | Only the starter tests, or one happy-path test at the end; no test exercises a failure script or a restart; asserts exact jittered values (flaky) or nothing about timing. |
| **End-to-end ownership** | Runs the CLI against `data/` (and the local receiver) at least once and points out the broken lines and what the report says. States the delivery guarantee (at-least-once) unprompted in Part 3. Finishes with what's done, what isn't, and the next risks (head-of-line blocking, file growth). | Never runs the CLI; never opens `events.jsonl`; leaves `delivery()` raising `NotImplementedError` or the CLI broken after refactoring; can't say what happens on a crash. |
| **Communication** | Narrates trade-offs ("audit before save means a crash may duplicate an audit line, never lose one"; "rewriting the whole file per attempt is fine at this size, here's what I'd do at 100x"). Asks sharp questions the spec leaves open (backfill for new subscriptions, ordering) and accepts "out of scope". | Long silences; asks questions the PART file answers (which status codes retry); can't explain why a timeout is or isn't safe to retry. |

## Hidden-test mapping

| Test file | Covers |
|---|---|
| `test_part1.py` | routing by type and `"*"` in file/subscription order, exact body, Content-Type, X-Event-Id, valid signature with `t=int(clock.time())`, delivered never re-sent, `delivery()` shape and `KeyError`, failed → pending → retried, ConnectError contained, audit lines (keys, attempt numbers, outcome, status_code, error, ts), `skipped_lines` (bad JSON, non-object, bad fields, empty id, duplicate id, blanks ignored), events appended later |
| `test_part2.py` | backoff ranges for attempts 1–4 and the 300 s cap, due exactly at `next_attempt_at` and not before, jitter varies, Retry-After exact (incl. > 300), at most one attempt per call, 4xx/3xx dead immediately, 408/429/5xx/ConnectError rescheduled, dead after `max_attempts` (default 5, 429 counted), report counts, failing subscriber doesn't block others, no sleeping; **change**: 5 s timeout on every request, timeout retryable, timeouts count towards `max_attempts` |
| `test_part3.py` | restart never re-sends delivered, new instance reports saved state before dispatching, pending schedule resumes exactly, attempt count survives restarts, dead stays dead, idempotent re-run at the same time (same and new instance), events appended between runs, audit appended across restarts, in-process crash propagates and earlier attempts stay saved, subprocess killed between send and save → at-least-once (acknowledged-and-saved not re-sent, unsaved re-sent) |

Use hidden-test results as evidence for **Correct execution** only; the other
